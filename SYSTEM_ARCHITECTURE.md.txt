# 🏛️ System Architecture & Design Decisions

> A technical deep-dive into the concurrency models, routing logic, and software design patterns powering the eSim Unified Tool Manager.

![Architecture Flow](./diagrams/01_system_architecture.png)

## <font color="#2563eb">**1. Architectural Pattern: Separation of Concerns (SoC)**</font>
The application strictly enforces a separation between the Presentation Layer and the Business Logic Layer to ensure maintainability and scalability.

* **Frontend (`src/gui.py`):** Handles all user interactions, custom rendering (via `CustomTkinter`), hardware storage calculations, and live animation loops (e.g., the 60FPS news ticker). 
* **Backend (`src/engine.py`):** The `SystemOrchestrator` acts as a headless backend. It handles subprocess management, OS-level environment verifications, and payload delivery. 

By decoupling these layers, the GUI remains highly responsive regardless of the backend I/O load.

## <font color="#2563eb">**2. Concurrency & Multi-Threading Model**</font>
Traditional Python GUIs (like standard `tkinter`) run on a single synchronous thread. Executing heavy network requests or file extractions on this thread causes the application window to freeze and trigger an OS-level "Not Responding" state.

To solve this, the Tool Manager wraps all deployment sequences in **Asynchronous Background Threads**:
```python
import threading
threading.Thread(target=process_install).start()
```
**Impact:** The main UI loop is never blocked. The system can smoothly render progress bar updates and push live telemetry logs to the console while the background thread handles the actual deployment logic.

## <font color="#2563eb">**3. OS-Aware Payload Routing Logic**</font>
Open-source dependencies are not distributed uniformly. The engine uses `platform.system()` to dynamically adjust its behavior based on both the host OS and the payload profile.

### A. Heavyweight Payloads (e.g., KiCad)
* **Profile:** >1GB, requires deep system registry integration and OS-specific setup wizards.
* **Execution Strategy:** Direct background downloading is unstable due to expiring security tokens and mirror redirects. Instead, the engine detects the host OS (Windows/Mac/Linux) and routes the user via a secure `webbrowser` gateway to the exact official download endpoint.

### B. Portable Binaries (e.g., Ngspice, Verilator)
* **Profile:** Lightweight, command-line driven, distributed as raw compressed archives (`bin`/`lib`).
* **Execution Strategy:** These do not require native OS installation wizards. The orchestrator triggers simulated background extraction protocols, keeping the user entirely within the application dashboard.

## <font color="#2563eb">**4. Pre-Flight Hardware Diagnostics**</font>
Rather than blindly attempting installations, the system implements defensive programming by running pre-flight checks:

* **Storage Telemetry:** Utilizes `shutil.disk_usage` to asynchronously calculate local `C:\` drive capacity, ensuring sufficient space before allowing heavy deployments.
* **Dependency Verification:** Iterates through binary paths to visually confirm which tools are already present on the user's local machine, updating the UI state to prevent redundant installations.
